# 02 — SPATIAL MATH：2.5D 空间与坐标契约

> **范围**：这份文档定义「3D 房间 + 世界内 2D 纸片」如何在同一场景中成立。
> 只确认用户描述过的空间目标。涉及数学的**坐标转换接口**属于技术契约，不暗示新的玩法规则。

## 1. 必须满足的空间事实

1. **[已确认]** 房间 / 场景由真实 3D 几何构成。
2. **[已确认]** 玩家角色与可交互物品的**可见部分**为二维纸片状。
3. **[已确认]** 特效允许采用 3D 方式，但灰盒阶段不要求制作正式特效。
4. **[已确认]** 摄像机构图参照用户提供的**第二张图**，而非当前第一张图的高空俯视盒子。
5. **[技术必需]** 角色与交互物品具有游戏世界中的位置，而不是固定在屏幕坐标上的贴图。
6. **[技术必需]** 交互检测、对象身份与对象的渲染组件应分离；换纸片显示不应改变交互对象本身。

## 2. 坐标层次（使用 Unreal 原生约定）

UE 世界坐标的技术基准：
- `World X, World Y`：水平位置分量。
- `World Z`：竖直高度。
- UE 默认世界坐标单位为 **厘米**；实际项目单位和比例尺需要核验。

**本原型不得引入另一个未经说明的独立「2D 游戏世界」。**

记录同一个世界对象的三个概念：

| 概念 | 含义 | 确定程度 |
|---|---|---|
| `WorldTransform` | 对象在 3D 场景的权威位置与朝向 | 技术必需 |
| `VisualPlane` | 贴在上述对象上的纸片表示 | 已确认视觉类型 |
| `InteractionShape` | 对象的物理交互 / 触发区域 | 具体形状待决定 |

### 2.1 地面角色与纸片显示的映射

对处于地板上的角色，记录：
- 逻辑位置 `P = (x, y, z)`。
- 地面接触点 `P_foot`（角色与当前地面的实际接触位置）。
- 纸片自身局部平面坐标 `(u, v)`。
- 局部水平方向单位向量 `U`。
- 局部竖直方向单位向量 `V`。

一个可用的**通用数学表达**：

`P_visual(u, v) = P_anchor + s_u * u * U + s_v * v * V`

约束：
- 对站立角色，`V` 应平行于世界向上方向 `(0, 0, 1)`。
- `U` 与 `V` 互相垂直；角色纸片是一个平面而非立体方块。
- `P_anchor` 与 `P_foot` 的关系由资产 Pivot / 视觉偏移建立，**不要求两者天然相等**。
- `s_u`, `s_v` 是显示尺寸换算；**具体数值留空**。
- 纸片面朝摄像机、面朝固定方向，还是随角色方向变化，**尚未决定**。
- 如果角色在倾斜地面上，贴地和纸片朝向的特殊处理，**尚未决定**。

**不可把 `P_visual` 直接改成任意 UI 屏幕位置来跳过世界空间关系。**

### 2.2 交互物的映射

- 可交互物有自己的 `WorldTransform`。
- 其可见表示属于世界内的 `VisualPlane`。
- 交互体与视觉纸片属于**同一个逻辑对象**，但技术上可分别定位与偏移。
- 纸片到底竖立于地面、附着在墙面或有其他朝向，**由具体对象配置决定，当前不统一猜测**。
- 建筑结构本身若同时具有可交互部分，结构网格与交互纸片如何分工：**待决定**。

### 2.3 世界坐标到画面

画面位置来自相机投影，而不是设计一个单独的 HUD 位置：

`ScreenPoint = Project(CameraViewProjection, WorldPoint)`

- 相机矩阵、对象视觉面、遮挡共同决定最终画面。
- 思想泡泡可跟随角色的世界锚点，但具体采用 World-space Widget 或屏幕投影 Widget：**待决定**。
- 思想泡泡的锚点高度、缩放规则、是否遮挡：**待决定**。

## 4. 平面朝向（必须作为独立配置）

- 所有纸片不得默认当作世界 XY 地板平面铺平。
- 地面站立角色应在画面中呈现**竖立的纸片**。
- 屏幕始终朝向相机的 Billboard、固定朝向、按角色运动朝向旋转，属于互斥或可组合方案，**尚未选定**。
- 如果采用 Billboard，需避免绕水平轴倾斜导致脚底脱离地面；但**采用 Billboard 本身尚未确定**。
- Sprite 正反面的材质双面配置与背面行为：**TBD**。

## 5. 遮挡与排序不变量

**[技术必需]**
- 3D 场景应能正确表现前后关系与遮挡。
- 纸片不应无条件绘制在所有墙体与场景物体最前面。
- 不能用 UI 的显示顺序替代真实的世界深度。

**[待决定]**
- 透明材质采用何种排序机制。
- 是否额外使用 Translucency Sort Priority。
- 多张纸片贴近或穿插时的先后规则。
- 同一对象的多层 Sprite 渲染顺序。

> `Sorting Layer` 是跨引擎的泛称；UE 的具体实现方式应在确认材质和 Paper2D / Mesh 方案后决定。

## 6. 移动和碰撞边界

- **[已确认]** 角色在场景中可移动，视觉是纸片。
- **[技术必需]** 视觉纸片薄，不等于其碰撞体必须是二维几何。
- **[待决定]** 地面移动是否允许自由的 X/Y 两方向。
- **[待决定]** 移动输入、角色朝向、移动速度、镜头对移动的反馈。
- **[待决定]** 碰撞形状与尺寸、纸片与碰撞体的中心偏移。
- **[待决定]** 是否存在跳跃、楼层、坡道等三维移动行为。
