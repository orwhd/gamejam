## 3. Pivot / Anchor 合同

### 3.1 地面角色

**[技术必需]**
- 角色的**可见底部接触点**应与角色所在的地面位置保持一致。
- 角色逻辑位置、视觉平面和碰撞体之间可以有明确偏移，但偏移必须稳定、可追踪。
- 动画、朝向调整不能让角色突然悬浮或穿进地面。

**[待决定]**
- Sprite 资源 Pivot 具体位于底边中心、底边其他位置还是中心。
- `VisualOffset` 的具体数值。
- 各角色身高与纸片尺寸。
- 人物朝左 / 朝右时是否采用镜像、旋转或不同图。

> **不要把「脚底必须落地」误写成「美术 Pivot 已被用户确定为底边中心」。**

### 3.2 场景可交互物

**[技术必需]**
- 纸片的可见位置与其实际交互对象绑定。
- 独立碰撞体可以不具备可见厚度。
- 墙面 / 地面对象的具体挂接方式可以不同。

**[待决定]**
- 每类物品的 Pivot 与视觉偏移。
- 可交互门与 3D 建筑结构的关联方式。
- 高亮、选中框、交互提示所在的锚点。

## 4. Sorting Layer / Depth（尚无用户确定的层级表）

**已确认的目标**
- 纸片处于 3D 世界里，应与墙体和前后物体具备可信的遮挡关系。
- 不能将所有人物、物品渲染为始终在最前的 HUD 层。

**暂未确定的规则**
- 不透明 / Masked / Translucent 材质选型：**TBD**。
- 是否使用 UE Translucency Sort Priority：**TBD**。
- 同一个角色若有多片纸片的绘制顺序：**TBD**。
- VFX 与 Sprite 的遮挡优先级：**TBD**。
- UI 泡泡的渲染顺序：**TBD**。

**引擎提醒**：`Sorting Layer` 是通用需求名，不能照搬 Unity 的 Sorting Layer API 来实现 UE 项目。具体渲染策略要根据实际组件与材质决定。

## 6. 灰盒资源验收

- [ ] 3D 墙体与地板建立合理室内空间，而非图一的高俯视盒子视觉。
- [ ] 角色 / NPC 的可见表示为纸片，而非 3D 方块。
- [ ] 可交互物品的可见占位为纸片；交互检测仍正确。
- [ ] 人物脚底与地面视觉接触成立。
- [ ] 移动时人物纸片、逻辑坐标、碰撞体不相互脱离。
- [ ] 前后遮挡体现真实世界空间关系。
- [ ] 没有为验证灰盒而强行加入正式材质、像素风格、场景家具和复杂动画。
- [ ] 若不能从 UE 编辑器运行验证，保持验收项为未通过 / 未验证。
