# 01 — GDD CORE：核心玩法与状态循环

## 1. 核心定义

- **[已确认]** 游戏正式名称：`Persona`；Game Jam 主题：`Director's Cut`。
- **[已确认]** 目标交付与操控：面向 Windows 提交（macOS 开发）；采用**键盘 + 鼠标**操作（键盘 `WASD` 控制角色移动、`E` 触发场景交互、`R` 随时重拍，鼠标操作 Persona 全屏剧本页与 UI 按钮）。
- **[已确认]** 当前关卡范围：**优先集中完成第一个「消防员」关卡场景的完整闭环**（后续关卡尚未设定，当前阶段不制作「下一关」流转逻辑，仅保留结算页重拍冲星与完成演出闭环）。
- **[已确认]** 玩家控制一个角色，通过**删减 Persona 预设文字块**，改变角色记忆、性格倾向和 / 或可执行行为。
- **[已确认]** Persona 的效果判定采用**确定性规则 / 标签映射**（不接入 AI / LLM 实时解释，确保解谜因果可控且可离线运行）。
- **[已确认]** 进度范围：采用**单局 / 按关重开**结构，不设跨退出持久化存档。
- **[已确认]** 删除经历不会改写世界历史；NPC 依然记得原本发生的事。
- **[已确认]** NPC 根据既定剧本行动；玩家通过实际操控自己的角色介入场景，使事件结果产生差异。
- **[已确认]** 玩家不仅编辑文字，还在场景中操控角色移动并与对象交互。

## 2. Persona 操作契约

| 项 | 规则 | 状态 |
|---|---|---|
| 编辑单位 | 由设计者预先划分的**文字块**，不是任意单词 | 已确认 |
| 可删除性 | 可按文字块分别设置 | 已确认 |
| 可重排性 | 数据结构保留 `can_reorder` 扩展字段；**灰盒原型阶段不启用重排玩法**，当前关卡全部设为不可重排 | 已确认 |
| 身份 | 不通过删减改变当前操控角色的基本身份 | 已确认 |
| 删除经历 | 当前角色忘记该经历；其他人和世界历史不随之改变 | 已确认 |
| 删除后自动变强 | **不成立**；例如删掉整个 `not fireproof` 不自动让消防员获得防火能力 | 已确认 |
| 删除与性格 / 能力的映射规则 | 每个文字块可显式绑定 `0..N` 个状态标签（可同时包含心理限制标签与正面认知/能力前提标签）；删除该块即同步移除其携带的所有标签，不自动赋予反向能力 | 已确认 |
| 改 Persona 的时机与界面形态 | **仅限每轮演出开始前（`Pre-Take`）在全屏纯文字剧本页编辑**（此时看不见 3D 房间）；点击「开拍（Start Take）」切入 3D 房间进入 `Active Take` 后隐藏剧本页并锁定编辑权限，现场碰壁后需重拍（`Restart Take` / 按 `R` 键）退回 `Pre-Take` 全屏剧本页修改 | 已确认 |
| 能否撤销 / 恢复文字块 | **单轮演出内剪除后不可单独恢复**；只能通过「重开本轮演出（`Restart Take` / 按 `R` 键）」将整份 Persona 与场景状态完整重置回初始状态 | 已确认 |

> **与现有工程的差异提示（交接给编程 Agent）**：现有原型 `ADCDirector` 默认测试占位 `bAllowEditingDuringTake = true` 允许演出中途编辑，后续实现需按上述 `[已确认]` 规则收敛为“仅开拍前编辑 + 重拍整轮重置”。

## 3. 交互契约

**[已确认]** 角色可移动，但 Persona 可阻止其执行具体交互。

**[示例]** 玩家控制消防员，试图进入发生火灾的建筑；由于角色认为必须服从上司命令，该交互不能执行。界面给出思想泡泡：

> I must obey my captain's orders... Last time I disobeyed him, it ended badly.

- **[已确认]** 交互失败要能反映**角色的心理原因**，而不是让玩家以为按钮失灵。
- **[已确认]** 思想泡泡提示粒度：采用**「表层抗拒想法 + 隐晦指向过去经历的心理线索」**，引导玩家联想到去 Persona 审视对应记忆，但不直接点破应删除哪一个文字块。
- **[已确认]** 文档仅约束英文文本的结构与语义槽位，具体英文词句保持留空，留待后续在 UE 编辑器配置时填写微调。
- **[已确认]** 删除相关过去经历仅让角色忘记；不保证自动反转所有属性，也不自动改变上司的记忆。

## 4. NPC 与结果

- **[已确认]** NPC 行动遵循预设的剧本；玩家不能靠修改自己的记忆直接修改 NPC 的记忆或世界历史。
- **[已确认]** 消防员关卡中，队长（Captain）的行为表现：**全程无台词，拦截在玩家通往火场的前方，双手撑开呈阻拦姿态**。
  - 当主角保留与队长的冲突/受罚记忆时，尝试突破/进门交互会被自身心理限制阻止，弹出英文思想泡泡。
  - 当主角在 `Pre-Take` 删除该记忆后，队长依然按原剧本撑手拦在门前，但主角不再受心理限制阻拦，可通过交互进入火场。
- **[已确认]** 同一事件因主角介入与否及行动顺序不同，产生不同的伤亡与灭火结果。

## 5. 消防员关卡规则与交互闭环

**[已确认]**
- **游戏内文本语言**：英文（English）。
- **本关 Persona 结构**：采用「固定身份/动机文字块 + 单向创伤可删文字块」（首关聚焦跑通核心因果循环，暂不设置删块丢失技能的负面惩罚）。
- **界面呈现与快捷控制**：
  - **`Pre-Take`（开拍前准备）**：呈现为**全屏纯文字剧本页**（此时看不见 3D 房间画面），玩家审阅并点击删减文字块，点击「开拍（Start Take）」后切入 3D 房间画面。
  - **`Active Take`（正式演出）**：切入全屏单固定 3D 室内透视画面，隐藏 Persona 剧本页并锁定编辑；靠近可交互目标时浮现 **`[E]` 交互提示**；支持按 **`R` 键随时快速重拍**（及点击 UI 重拍按钮）退回全屏 `Pre-Take` 剧本页。
- **室内空间动线布局（多处火点 + S 形动线 + 侧角分岔工具位）**：
  - **多处阻挡火点与 S 形通道**：室内预设**多处起火点**（具体数量 `N` 在编辑器配置）。未扑灭的火点作为**不可直接穿过的物理阻挡**，与室内灰盒结构共同围出通往深处受困者的 **S 形绕行通道**（不灭火也可沿 S 形通道绕行至深处救人；扑灭某处火点后该处阻挡消除，打通通行捷径）。
  - **物理分岔工具位**：便携灭火工具（灭火器/水枪）放置在**远离救援主路的房间侧角（物理分岔位）**，使「绕去侧角取工具」与「沿 S 形动线直奔深处救人」形成两条反方向路线，依靠物理绕路距离与多处灭火读条耗时拉开先后顺序差异。
- **空间闭环交互细则（按 `E` 触发上下文交互）**：
  1. **进门**：在门前浮现 `[E]` 提示，按 `E` 突破阻拦/开门走入 3D 室内（非生硬坐标瞬移）。
  2. **取工具与读条灭火**：
     - 走到侧角分岔处按 `E` 拾取灭火器/水枪；若未持有工具靠近火点，提示需先获取灭火工具。
     - 持有工具靠近任一未灭火点时，**按住 `E` 持续喷射读条**（单处读条约 `1.5–3` 秒，具体秒数编辑器可调；**中途松开 `E` 或移动走开即中断喷射**，方便玩家随时改变主意先去救人）。
     - 每扑灭 1 处火点，消除该处阻挡并**适当延缓「火满全屋（`RoomEngulfed`）」的剩余倒计时**（单处延缓秒数编辑器可配）；**扑灭室内全部火点**后，判定火灾扑灭并点亮 **+1 星**。
  3. **紧随护送救人**：
     - 靠近存活（未受伤或已受伤）受困者按 `E` 后，受困者**自动紧随主角移动**（不占用手持工具状态，可同时持有灭火工具），带领受困者**踏入门外安全区即自动完成救援结算**（无需再按 `E`）。
     - 若火势已推进至受困者**身亡**阶段（星容器扣至 `1`），受困者切换为**倒下状态纸片，直接隐藏 `[E]` 交互提示且按 `E` 无反应**。
- **主角生命规则**：主角消防员本身不设血条与死亡判定；即使火势最终铺满全屋，此前已护送出门的救援成果依然保留。
- **火势四阶段蔓延与无秒表视觉表现**：不采用抽象明面倒计时，通过**火点纸片尺寸逐阶扩张 + 受困者状态纸片切换**直观传达恶化：
  1. `初始起火（Active）`：多处火点处于初始燃烧尺寸，受困者为「待援未受伤」纸片；
  2. `波及受伤（CivilianInjured）`：火点视觉扩张变大，未获救受困者切换为「受伤状态」纸片（闪现星容器 `3 → 2`）；
  3. `波及身亡（CivilianDead）`：火势进一步扩张，未获救受困者切换为「倒下遇难」纸片并移除交互（闪现星容器 `2 → 1`）；
  4. `铺满全屋（RoomEngulfed）`：全屋火光覆盖铺满，强制结束本轮并进入结算。
- **三星路线博弈（当前灰盒直接开放达成 3/3 星）**：玩家在 `Pre-Take` 删掉受罚记忆进入室内后，若**优先沿 S 形通道绕火直奔深处救人出门（无伤 +2 星），再折返侧角取工具逐一灭完多处火点（每灭一处延缓全屋火满，全灭 +1 星）**，即可达成 **`3 / 3` 满星**；若先绕去侧角拿工具并停下读条灭火，救援延迟将导致受困者受伤（星容器 `3 → 2`），最终达成 **`2 / 2`（2 星）**。

**[编辑器配置留空项：文档仅约束结构与语义，不在代码规则层写死]**
- 各 Persona 文字块、门前受阻思想泡泡、未拿工具提示及 UI 按钮的具体英文词句（保持留空，在 UE 编辑器中配置）。
- 初始火点具体数量、单处火点按住 `E` 喷射秒数、每灭一处火点延缓全屋火满的秒数、以及火势各蔓延阶段的具体秒数阈值（均在编辑器中开放配置与实测校准）。

## 6. 核心演出循环（已确认阶段顺序）

1. **开拍前准备（`Pre-Take` 全屏剧本页）**：呈现全屏纯文字剧本页（看不见 3D 房间，世界暂停），玩家审阅初始 Persona 文字块（首轮可直接不剪辑开拍，也可先删减可编辑文字块）。
2. **正式开拍（`Active Take` 切入 3D 房间）**：点击开拍切入全屏单固定 3D 室内透视画面，隐藏剧本页并锁定 Persona 编辑权限；队长无台词撑手拦截在门前，室内多处火点开始按阶段演化。
3. **心理受阻反馈**：若当前 Persona 携带限制标签阻止进门交互，门前按 `E` 时主角头顶弹出英文思想泡泡（表层抗拒想法 + 隐晦指向过去经历的心理线索）。
4. **重拍重置（`Restart Take` / 按 `R` 键）**：玩家在碰壁或结算后按 `R` 键（或点击重拍按钮），退回 `Pre-Take` 全屏纯文字剧本页，整份 Persona、角色位置、星容器、全部火点与受困者状态完整恢复至初始状态。
5. **剪辑与再次开拍**：玩家在 `Pre-Take` 全屏剧本页删掉对应的记忆文字块（本轮内不可单独恢复），再次点击开拍切入 `Active Take`。
6. **介入改变结局**：限制标签消失后，玩家突破进入室内，在「沿 S 形动线先救人」与「去侧角分岔位取工具按住 `E` 灭多处火」之间抉择行动；达成星级或容器变化时触发即时闪现的星容器反馈，直至满足单轮结束条件进入结算。

**验收重点**：玩家能清晰感知「现场碰壁线索 → 按 `R` 退回全屏剧本页剪除记忆块 → 新一轮演出解锁交互并通过动线规划达成满星」的因果闭环。

## 7. 动态星容器反馈与单轮结算规则（已确认）

### 7.1 即时闪现的「星容器」UI 机制
- **非常驻显示**：星容器**不是**一直挂在屏幕上的常驻 HUD，仅在**星级增加**或**星容器上限扣减**的事件发生瞬间**即时闪现提示**，随后隐去（结算界面再完整展示最终结果）。
- **初始上限**：每轮开始时默认拥有 **3 个空心星容器**（`☆ ☆ ☆`），暗示场上存在待完成的目标。
- **点亮规则（共 3 星来源）**：
  - **扑灭室内全部火点**：所有预设火点均被扑灭时，立即点亮 **+1 颗星**（每灭单处火点仅消除该处阻挡并延缓全屋火满，不单独加星）。
  - **救出受困者（已受伤状态）**：紧随护送踏入门外安全区时，立即点亮 **+1 颗星**。
  - **无伤救出受困者（未受伤状态）**：紧随护送踏入门外安全区时，立即点亮 **+2 颗星**（含存活救出 1 星 + 无伤 1 星）。
- **容器上限实时扣减规则**：
  - 当火势蔓延波及受困者导致其**受伤**时：失去无伤可能，受困者切换受伤纸片，空心容器上限即时减少 1 个（闪现提示 **`3 容器 → 2 容器`**）。
  - 当火势继续蔓延导致受困者**身亡**时：失去救活可能，受困者切换倒下纸片并移除 `[E]` 交互，空心容器上限再即时减少 1 个（闪现提示 **`2 容器 → 1 容器`**）。

### 7.2 最终星级判定表

| 最终客观结果 | 最终获得星数 | 结算时对应的星容器状态 |
|---|---|---|
| 火点未全灭 + 受困者未救出 | **0 星** | `0 / 1`（若火满全屋致受困者已遇难） |
| 仅扑灭全部火点（受困者已遇难未救出） | **1 星** | `1 / 1` |
| 仅救出已受伤受困者（火点未全灭，直至火满全屋收工） | **1 星** | `1 / 2` |
| 仅无伤救出受困者（火点未全灭，直至火满全屋收工） | **2 星** | `2 / 3` |
| 扑灭全部火点 + 救出已受伤受困者 | **2 星** | `2 / 2` |
| 扑灭全部火点 + 无伤救出受困者 | **3 星** | `3 / 3`（当前灰盒已开放：沿 S 路线优先护送无伤出门再取工具灭完所有火即可达成） |

### 7.3 单轮演出（Take）自动结束条件
满足以下任一条件时，本轮演出立即结束并弹出结算页（支持重拍冲星或结束演出，当前不设下一关入口）：
1. **达成当前容器满星**：`当前已获得星数 == 当前剩余星容器总数`（由于每次目标永久失效都会同步扣减容器数，只要把当前仍可挽救的目标全部完成——无论是 `3/3`、`2/2` 还是 `1/1`——都会自然填满剩余容器并立即收工，不会出现空房卡死）。
2. **火势蔓延铺满整个房间**：火灾彻底失控，强制结束本轮演出（此时玩家此前已护送出门所获得的救援星数予以保留）。

## 8. 当前灰盒原型验收边界与交接清单（供编程 Agent 承接）

**应验证的核心设计闭环：**
- `Pre-Take` 为全屏纯文字剧本页（看不见 3D 房间），仅在此阶段允许删减可编辑文字块；点击开拍切入 3D 房间进入 `Active Take` 后隐藏剧本页并锁定编辑，支持 `R` 键随时重拍整轮重置退回全屏 `Pre-Take`。
- 队长全程无台词、双手撑开拦在门前；靠近可交互对象浮现 `[E]` 提示；未删受罚记忆时按 `E` 进门被拒并弹出英文思想泡泡（表层抗拒 + 隐晦经历线索）；删块重拍后可突破走入室内。
- 室内空间动线与交互闭环：多处阻挡火点围出 S 形救援通道，灭火工具位于远离救援主路的侧角分岔位；按住 `E` 喷射读条灭火（松手/走开中断，每灭一处消除该处阻挡并延缓全屋火满，全灭 +1 星）；靠近存活受困者按 `E` 紧随护送，踏入门外安全区自动结算（受困者身亡后切换倒下纸片并移除 `[E]` 交互）。
- 火势四阶段无秒表视觉演化（火点逐阶扩张 + 受困者「未受伤 / 受伤 / 倒下」纸片切换 + 全屋火满结算）与非常驻即时闪现星容器反馈，且优先沿 S 路线救人再折返灭完所有火可拿满 `3/3` 星。
- `Active Take` 全程单固定室内 3D 透视机位（`FOV 55°–65° / 俯角 5°–15°`）同屏可见墙、天花板、地面与敞开门口拦路区；人物与交互物均为底边中心接地的竖直 2D `Masked` 纸片（见 `02_SPATIAL_MATH.md` 与 `05_ASSET_PIPELINE.md`）。
