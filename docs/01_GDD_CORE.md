# 01 — GDD CORE：核心玩法与状态循环

## 1. 核心定义

- **[已确认]** 游戏正式名称：`Persona`；Game Jam 主题：`Director's Cut`。
- **[已确认]** 目标交付与操控：面向 Windows 提交（macOS 开发）；采用**键盘 + 鼠标**操作（键盘控制角色移动与场景交互，鼠标操作 Persona 面板）。
- **[已确认]** 玩家控制一个角色，通过**删减 Persona 预设文字块**，改变角色记忆、性格倾向和 / 或可执行行为。
- **[已确认]** Persona 的效果判定采用**确定性规则 / 标签映射**（不接入 AI / LLM 实时解释，确保解谜因果可控且可离线运行）。
- **[已确认]** 进度范围：采用**单局 / 按关重开**结构，不设跨退出持久化存档。
- **[已确认]** 删除经历不会改写世界历史；NPC 依然记得原本发生的事。
- **[已确认]** NPC 根据既定剧本行动；玩家通过实际操控自己的角色介入场景，使事件结果产生差异。
- **[已确认]** 玩家不仅编辑文字，还在场景中操控角色移动并与对象交互。

## 2. Persona 操作契约

| 项 | 规则 | 状态 |
|---|---|---|
| 编辑单位 | 由设计者预先划分的**文字块**，不是任意单词 | 已确认 |
| 可删除性 | 可按文字块分别设置 | 已确认 |
| 可重排性 | 数据结构保留 `can_reorder` 扩展字段；**灰盒原型阶段不启用重排玩法**，当前关卡全部设为不可重排 | 已确认 |
| 身份 | 不通过删减改变当前操控角色的基本身份 | 已确认 |
| 删除经历 | 当前角色忘记该经历；其他人和世界历史不随之改变 | 已确认 |
| 删除后自动变强 | **不成立**；例如删掉整个 `not fireproof` 不自动让消防员获得防火能力 | 已确认 |
| 删除与性格 / 能力的映射规则 | 每个文字块可显式绑定 `0..N` 个状态标签（可同时包含心理限制标签与正面认知/能力前提标签）；删除该块即同步移除其携带的所有标签，不自动赋予反向能力 | 已确认 |
| 改 Persona 的时机 | **仅限每轮演出开始前（`Pre-Take`）编辑**；开拍进入 `Active Take` 后锁定编辑权限，现场碰壁后需重拍（`Restart Take`）回到开拍前修改 | 已确认 |
| 能否撤销 / 恢复文字块 | **单轮演出内剪除后不可单独恢复**；只能通过「重开本轮演出（`Restart Take`）」将整份 Persona 与场景状态完整重置回初始状态 | 已确认 |

> **与现有工程的差异提示（交接给编程 Agent）**：现有原型 `ADCDirector` 默认测试占位 `bAllowEditingDuringTake = true` 允许演出中途编辑，后续实现需按上述 `[已确认]` 规则收敛为“仅开拍前编辑 + 重拍整轮重置”。

## 3. 交互契约

**[已确认]** 角色可移动，但 Persona 可阻止其执行具体交互。

**[示例]** 玩家控制消防员，试图进入发生火灾的建筑；由于角色认为必须服从上司命令，该交互不能执行。界面给出思想泡泡：

> I must obey my captain's orders... Last time I disobeyed him, it ended badly.

- **[已确认]** 交互失败要能反映**角色的心理原因**，而不是让玩家以为按钮失灵。
- **[已确认]** 思想泡泡提示粒度：采用**「表层抗拒想法 + 隐晦指向过去经历的心理线索」**，引导玩家联想到去 Persona 审视对应记忆，但不直接点破应删除哪一个文字块。
- **[已确认]** 文档仅约束英文文本的结构与语义槽位，具体英文词句保持留空，留待后续在 UE 编辑器配置时填写微调。
- **[已确认]** 删除相关过去经历仅让角色忘记；不保证自动反转所有属性，也不自动改变上司的记忆。

## 4. NPC 与结果

- **[已确认]** NPC 行动遵循预设的剧本；玩家不能靠修改自己的记忆直接修改 NPC 的记忆或世界历史。
- **[已确认]** 消防员关卡中，队长（Captain）的行为表现：**全程无台词，拦截在玩家通往火场的前方，双手撑开呈阻拦姿态**。
  - 当主角保留与队长的冲突/受罚记忆时，尝试突破/进门交互会被自身心理限制阻止，弹出英文思想泡泡。
  - 当主角在 `Pre-Take` 删除该记忆后，队长依然按原剧本撑手拦在门前，但主角不再受心理限制阻拦，可通过交互进入火场。
- **[已确认]** 同一事件因主角介入与否及行动顺序不同，产生不同的伤亡与灭火结果。

## 5. 消防员关卡规则与交互闭环

**[已确认]**
- **游戏内文本语言**：英文（English）。
- **本关 Persona 结构**：采用「固定身份/动机文字块 + 单向创伤可删文字块」（首关聚焦跑通核心因果循环，暂不设置删块丢失技能的负面惩罚）。
- **轻度空间闭环交互（按 `E` 触发上下文交互）**：
  1. **进门**：在门前按 `E` 突破阻拦/开门走入 3D 室内（非生硬坐标瞬移）。
  2. **灭火**：需先在场景中拾取或开启灭火工具（如灭火器/水枪），再靠近火源按 `E` 灭火。
  3. **救人**：靠近受困者按 `E` 交互，并将其护送/带领至门外安全区才算完成救援。
- **主角生命规则**：主角消防员本身不设血条与死亡判定；即使火势最终铺满全屋，此前已护送出门的救援成果依然保留。
- **火势分阶段蔓延**：不采用抽象明面倒计时，而是由火势在房间内分阶段蔓延驱动节奏：
  `初始起火` → `蔓延波及受困者使其受伤` → `继续蔓延致受困者身亡` → `蔓延铺满整个房间（强制结束本轮）`。
- **三星路线博弈（当前灰盒直接开放达成 3/3 星）**：废除旧版“三星暂置”限制。玩家在 `Pre-Take` 删掉受罚记忆进入室内后，若**优先护送受困者无伤出门、再拾取/开启灭火工具扑灭火灾**，可直接达成 **`3 / 3` 满星**；若先去灭火导致救援延迟，受困者被火势波及受伤（星容器扣减 `3 → 2`），则最终达成 **`2 / 2`（2 星）**。

**[编辑器配置留空项：文档仅约束结构与语义，不在代码规则层写死]**
- 各 Persona 文字块与受阻思想泡泡的具体英文词句（保持留空，在 UE 编辑器中配置）。
- 火势各蔓延阶段的具体秒数阈值（需在编辑器中开放配置，使“先救人后灭火可无伤 3 星、先灭火后救人会受伤 2 星”的时间窗口可调）。

## 6. 核心演出循环（已确认阶段顺序）

1. **开拍前准备（`Pre-Take`）**：世界暂停，玩家审阅初始 Persona 文字块（首轮可直接不剪辑开拍，也可先删减可编辑文字块）。
2. **正式开拍（`Active Take`）**：锁定 Persona 编辑权限，队长无台词撑手拦截在门前，室内火势开始按阶段演化。
3. **心理受阻反馈**：若当前 Persona 携带限制标签阻止进门交互，主角头顶弹出英文思想泡泡（表层抗拒想法 + 隐晦指向过去经历的心理线索）。
4. **重拍重置（`Restart Take`）**：玩家在碰壁或结算后触发重拍，整份 Persona、角色位置、星容器、火势与受困者状态完整恢复至初始状态，回到 `Pre-Take`。
5. **剪辑与再次开拍**：玩家在 `Pre-Take` 删掉对应的记忆文字块（本轮内不可单独恢复），再次进入 `Active Take`。
6. **介入改变结局**：限制标签消失后，玩家突破进入室内，执行取工具灭火与护送救人；达成星级或容器变化时触发即时闪现的星容器反馈，直至满足单轮结束条件进入结算。

**验收重点**：玩家能清晰感知「现场碰壁线索 → 重拍前剪除记忆块 → 新一轮演出解锁交互并改变结果」的因果闭环。

## 7. 动态星容器反馈与单轮结算规则（已确认）

### 7.1 即时闪现的「星容器」UI 机制
- **非常驻显示**：星容器**不是**一直挂在屏幕上的常驻 HUD，仅在**星级增加**或**星容器上限扣减**的事件发生瞬间**即时闪现提示**，随后隐去（结算界面再完整展示最终结果）。
- **初始上限**：每轮开始时默认拥有 **3 个空心星容器**（`☆ ☆ ☆`），暗示场上存在待完成的目标。
- **点亮规则（共 3 星来源）**：
  - **扑灭火灾**：立即点亮 **+1 颗星**。
  - **救出受困者（已受伤状态）**：护送至安全区时，立即点亮 **+1 颗星**。
  - **无伤救出受困者（未受伤状态）**：护送至安全区时，立即点亮 **+2 颗星**（含存活救出 1 星 + 无伤 1 星）。
- **容器上限实时扣减规则**：
  - 当火势蔓延波及受困者导致其**受伤**时：失去无伤可能，空心容器上限即时减少 1 个（闪现提示 **`3 容器 → 2 容器`**）。
  - 当火势继续蔓延导致受困者**身亡**时：失去救活可能，空心容器上限再即时减少 1 个（闪现提示 **`2 容器 → 1 容器`**）。

### 7.2 最终星级判定表

| 最终客观结果 | 最终获得星数 | 结算时对应的星容器状态 |
|---|---|---|
| 火未扑灭 + 受困者未救出 | **0 星** | `0 / 1`（若火满全屋致受困者已遇难） |
| 仅扑灭火灾（受困者已遇难未救出） | **1 星** | `1 / 1` |
| 仅救出已受伤受困者（火未扑灭，直至火满全屋收工） | **1 星** | `1 / 2` |
| 仅无伤救出受困者（火未扑灭，直至火满全屋收工） | **2 星** | `2 / 3` |
| 扑灭火灾 + 救出已受伤受困者 | **2 星** | `2 / 2` |
| 扑灭火灾 + 无伤救出受困者 | **3 星** | `3 / 3`（当前灰盒已开放：优先护送无伤出门再取工具灭火即可达成） |

### 7.3 单轮演出（Take）自动结束条件
满足以下任一条件时，本轮演出立即结束并进入结算：
1. **达成当前容器满星**：`当前已获得星数 == 当前剩余星容器总数`（由于每次目标永久失效都会同步扣减容器数，只要把当前仍可挽救的目标全部完成——无论是 `3/3`、`2/2` 还是 `1/1`——都会自然填满剩余容器并立即收工，不会出现空房卡死）。
2. **火势蔓延铺满整个房间**：火灾彻底失控，强制结束本轮演出（此时玩家此前已护送出门所获得的救援星数予以保留）。

## 8. 当前灰盒原型验收边界与交接清单（供编程 Agent 承接）

**应验证的核心设计闭环：**
- 仅在 `Pre-Take` 开拍前允许删减可编辑文字块；进入 `Active Take` 后编辑锁定，单轮内不可单块恢复，仅通过 `Restart Take` 整轮重置。
- 队长全程无台词、双手撑开拦在门前；未删受罚记忆时按 `E` 进门被拒并弹出英文思想泡泡（表层抗拒 + 隐晦经历线索）；删块重拍后可突破进入室内。
- 室内轻度空间交互闭环：开门走入室内 → 拾取/开启灭火工具再对火源按 `E` 灭火 → 靠近受困者按 `E` 护送至门外安全区。
- 火势四阶段蔓延（起火 → 受困者受伤［容器 `3→2`］ → 受困者身亡［容器 `2→1`］ → 火满全屋强制收工）与非常驻即时闪现星容器反馈，且优先救人再灭火可拿满 `3/3` 星。
- 全程单固定室内 3D 透视机位（`FOV 55°–65° / 俯角 5°–15°`）同屏可见墙、天花板、地面与敞开门口拦路区；人物与交互物均为底边中心接地的竖直 2D `Masked` 纸片（见 `02_SPATIAL_MATH.md` 与 `05_ASSET_PIPELINE.md`）。

**现有 `DirectorCutJam/` 工程与本正式约束的主要偏差（待编程 Agent 重构对齐）：**

| 模块 | 现有早期工程现状 | 已确认正式约束要求 |
